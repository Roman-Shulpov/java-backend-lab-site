# Если прогресс не дошёл до телефона

Цепочка: **браузер компьютера → закрытый java-backend-lab → телефон и виджет**.
`java-backend-lab-site` содержит только публичный сайт, личного прогресса там нет.

## На компьютере огонёк есть, на телефоне нет

1. На том компьютере и в том браузере, где есть выполненный урок, открой **Помощь → Скачать копию прогресса**. Не очищай данные браузера.
2. В [настройках ключа](https://github.com/settings/personal-access-tokens) выбери **Only select repositories → Roman-Shulpov/java-backend-lab** (без `-site`). Разрешение **Contents → Read and write**, Metadata остаётся Read-only. Actions не нужно. Нажми **Update**.
3. В кабинете **Помощь → Изменить подключение**: ветка `main`, исправленный ключ. При замене ключа вставь его заново. Для своего устройства можно включить запоминание.
4. Дождись **✓ В GitHub**. «Сохранено здесь» означает, что отправка ещё не завершена. Если ошибка осталась, сохрани её текст.
5. В кабинете телефона тоже подключи GitHub и нажми синхронизацию. В Scriptable: **Java Lab → ▶ → Проверить синхронизацию**. Должны совпасть ветка `main` и серия.

У виджета отдельный ключ в Keychain: доступ к тому же закрытому репозиторию, **Contents → Read-only**. Если нужно, выбери в Scriptable «Заменить ключ». В параметре домашнего виджета оставь `main` либо пустое значение. Выбранный скрипт должен быть именно Java Lab.

Виджет запрашивает обновление через 15 минут; iOS может обновить позднее. Для проверки текущих данных запусти скрипт вручную. [Ограничение Scriptable](https://docs.scriptable.app/listwidget/#refreshafterdate).

## Что означает ошибка

| Сообщение | Действие |
|---|---|
| Ключ не видит закрытый репозиторий | Проверь выбор **без -site**, Contents и Update, переподключи ключ |
| Ключ не даёт нужного доступа | Проверь срок действия и Contents: Read and write для сайта |
| Ветка не найдена | Помощь → Изменить подключение → `main`; то же в Scriptable |
| Ветка доступна, файл не читается | Проверь Contents, затем наличие `progress/state.json` в закрытом репозитории; не создавай пустой файл поверх старого |
| Нет ответа / временное ограничение | Сохрани копию, повтори позже; ключ менять не требуется |
| Запись изменена на двух устройствах | Скачай копии с обоих устройств; не перезаписывай одну другой вслепую |

GitHub может отвечать **404** при отсутствии доступа к закрытому ресурсу: это не доказательство удаления файла. [Документация GitHub](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api).

## Команды на Windows

Открой PowerShell и выполни:

```powershell
Set-Location 'C:\Users\Maksim\Desktop\Java-Backend-Lab'
python -X utf8 app/doctor.py --backup
git status
```

Диагностика проверит доступ Git, ветку и файл в `origin/main`. Скопирует **локальный файл** прогресса в `tmp/recovery`; браузерную копию скачивают отдельно кнопкой в кабинете. Авторизация Git и ключ в браузере независимы: успешная диагностика Git не проверяет ключ сайта.

Если нужно получить обновления кода, а `git status` сообщает, что рабочая папка чистая:

```powershell
git pull --ff-only
```

Если есть изменения, сначала сохрани свою работу через IntelliJ/Git. Если pull сообщает о расхождении истории или конфликте — остановись и сохрани текст ошибки. Не используй `reset --hard`, `clean` или `push --force` для починки синхронизации.

Для локального кабинета, если он не запущен:

```powershell
python app/server.py
```

Обычная работа через GitHub Pages не требует локального сервера. После обновления сайта нажми Ctrl+F5; данные браузера при этом не удаляются. Ключи не отправляй в чат и не добавляй в код или коммиты.
